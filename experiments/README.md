# 별도 후보 모음 실험

현재 튜닝 작업이 끝난 뒤 **기준선 포함 8개 방법**을 순차 비교한다. Optuna trial을 추가하는 것이 아니라 아래 고정된 후보들의 차이를 확인하는 탐색 실험이다. 모든 모델은 CUDA 필수이며 GPU 사전 검사 실패 시 중단한다.

| 후보 | 기준선과 다른 점 |
|---|---|
| baseline | 600회 고정 LightGBM, 두 예보 라운드 평균 |
| l1_loss | 절대오차 손실 |
| simple_tree | 잎 수 31, 최소 잎 표본 500 |
| recent_2years | 각 예측 시작 시점 기준 최근 2년만 학습 |
| round17_only | 17시 예보 모델만 사용 |
| extra_trees | 무작위 분할 후보 사용 |
| no_direct_coordinates | 직접 위도·경도 입력 제외, 태양 위치 계산은 유지 |
| tiny_tree | 잎 수 7 |

K=1, 600회 학습, 참조 G1/G2 배정을 고정한다. 최신 외부 평가월(2025년 5월) 이전 내부 모델 선택 블록인 2024년 5월~2025년 4월의 매월 1~10일을 비교한다. 모든 예측은 해당 블록 이전 자료만 학습한다. 외부 평가 정답은 열지 않는다. 최근 2년은 현재 날짜가 아니라 해당 과거 학습 마감에서 계산한다.

본 실험은 8개 후보 × 12개월의 **96개 블록**, 17시 전용 후보를 제외하면 두 모델씩 학습하므로 **총 180개 모델**이다. 한 번에 하나씩 실행하며 CPU 보조 작업은 4스레드다. smoke는 한 내부 월·12회 학습으로 15개 모델을 실행한다. 완료 시간을 보장하지 않으며 현재 본 학습이 오래 걸리면 대기도 그만큼 길어진다.

## 현재 학습 뒤 자동 실행

Windows에서 이 변경을 push하고 GB10의 `ai_sim`에서 pull한다. 이번 변경은 `experiments/`와 해당 테스트·문서만 추가하며 기존 `scripts/` 파일은 바꾸지 않는다. 현재 학습을 다시 시작하거나 설치 환경을 바꿀 필요가 없다.

```bash
git pull origin main
nohup bash experiments/queue_candidates.sh tunning_cuda_1028 > candidates_queue.log 2>&1 < /dev/null &
tail -f candidates_queue.log
```

`tunning_cuda_1028`은 사용자가 알려준 철자를 그대로 사용한다. 이 경로에 manifest가 없으면 `results/tunning_cuda_1028`을 확인한다. 둘 다 없으면 오류로 끝나므로 실제 실행 폴더를 지정한다. 이 명령은 한 번만 실행한다. Linux `flock`으로 같은 큐의 중복 실행을 막는다.

대기 중에는 기존 실행 폴더의 `summary.json`을 60초마다 읽을 뿐 GPU 학습을 시작하지 않는다. `status=complete`, `all_12_months=true`, smoke 아님을 모두 확인한 뒤 다음 순서로 실행한다.

1. CUDA 검사와 8개 후보 smoke → `results/tuning_smoke_candidates_v1/`
2. 모두 성공하면 본 비교 → `results/candidates_cuda_v1/`

기존 학습이 실패·중단되면 완료 표시가 없으므로 추가 실험도 시작하지 않고 대기한다. smoke가 실패하면 본 비교는 실행하지 않는다. 전체 시스템의 다른 GPU 프로세스를 감시하는 것은 아니며 지정한 본 학습의 완료만 확인한다.

큐가 종료된 후 같은 명령을 다시 실행하면 manifest가 있는 결과는 `--resume`으로 이어간다. 완료된 후보·월의 저장 모델과 예측 파일 해시를 확인하고 건너뛴다. 코드·입력·스레드·라이브러리 버전 변경은 다른 실행 폴더를 요구한다. 재시작에 필요한 모델과 Parquet은 Git에 넣지 않으며 실행 장비에 보존한다.

직접 실행할 경우:

```bash
source .venv-cuda/bin/activate
python -u experiments/screen_candidates.py --output-dir results/candidates_cuda_manual --threads 4
```

## 결과 해석

`SUMMARY.md`와 `summary.json`에 완료 개월 수·월 동일 가중 NMAE·최악 월·완전 실적 시간의 W를 기록한다. 각 블록의 `comparison.json`에는 기준선과의 잔차 상관 및 예측 차이도 저장한다. 모든 후보의 같은 12개월이 끝나기 전에는 최우수 후보를 표시하지 않는다. 결측 정산은 N/A이며 0점으로 처리하지 않는다.

**이 결과는 내부 구간에서 후보를 고르는 탐색용이다.** 최우수 후보의 점수를 독립 검증 성능으로 주장하거나 기존 본 학습의 외부 월 점수와 직접 비교하지 않는다. 다음 단계에서 유망 후보를 기존 내부 선택→별도 혼합 선택→외부 평가 절차에 넣어 검증한다. 잔차 상관이 낮아도 혼합 개선이 보장되지는 않는다.

## 검증 범위

로컬 테스트는 기준선 특성·예측 처리 일치, 좌표 제외 후 태양 특성 보존, 과거 기준 2년 제한, 외부 평가 접근 차단, 후보의 CUDA 설정, 완료 대기 조건, 불완전 결과 순위 금지, 모의 GPU를 이용한 17시 전용 학습·저장·재시작을 확인한다. 실제 GPU의 8개 후보 호환성과 성능은 GB10에서 큐의 smoke가 확인한다. 로컬 Windows에서 CUDA 학습 성공을 확인한 것으로 해석하지 않는다.
