# DataEn 2026 OIBC 공개 자료 조사

조사일: 2026-10-26 (KST)

**후속 공지(2026-10-27):** 아래 내용은 조사 당시 공개 자료의 기록이다. 이후 [운영팀 Q&A](https://dataen.ai/challenge/2026/board/cfe4c0fc-7951-4ee9-b293-4730e42029ec)가 공개·상업적 이용 가능한 외부 소스·모델의 사용을 허용했고, [형식 Validator 공지](https://dataen.ai/challenge/2026/board/4984651b-a17a-4d2f-8350-fbf36ffc037b)는 `scoring.py`를 배포하지 않는다고 밝혔다. 현재 적용 규정은 [대회 데이터 가이드라인](../../competition_guidelines.md)을 따른다.

이 문서는 2026 OIBC 대회 공개 페이지, 로그인된 참가 화면에서 보이는 공개 안내, POSTECH 공식 공고를 기존 프로젝트 문서와 대조한 결과다. 실제 데이터 파일은 참가 신청 승인 전에는 내려받을 수 없어 파일 구조를 직접 검증하지 못했다. 2024 FAQ와 DataEn 일반 사용자 가이드는 2026 대회 규정으로 사용하지 않았다.

## 1. 조사 결론

- 과제는 제공된 태양광 발전소 전체를 **2개의 집합자원**으로 구성하고, 각 집합자원의 **하루 전 발전량**을 예측해 전체 정산금 `S`를 최대화하는 것이다.
- 공식 웹 본문에는 **`S = 매전수익 - 예측 오차 페널티 W`**까지만 보이지만, 공식 온라인 설명회는 `W = Σ(0.1 × SMP × k × 집합별 절대오차)` 구조와 `k` 값을 설명한다. 아래 6절에 근거와 자동 자막의 한계를 함께 적었다.
- 공식 허용 언어는 **Python 또는 R**이다. 프로젝트의 Python 단독 사용은 참가 규정이 아니라 사용자의 구현 선택이다.
- 조사 당시에는 외부 데이터·모델 금지로 해석했으나, 후속 Q&A가 공개·상업적 이용 가능한 외부 소스·모델 사용을 허용했다. DEM도 조건을 확인한 뒤 모델 입력 후보로 둘 수 있다.
- 대회 기간 제출은 CSV이며 1일 최대 3회, 대회 전체 최대 20회다. 정확한 CSV 열·행 스키마와 제출 템플릿은 아직 공개 화면에서 확인할 수 없다.
- 조사 당시에는 코드·발표자료 제출을 상위 7개 팀 대상으로 파악했다. 후속 Q&A는 장려상 수상 팀에도 코드 제출을 요구할 수 있다고 밝혔다. 코드는 전처리·학습·추론을 재실행할 수 있어야 한다.
- 제공 데이터 파일은 참가 신청 승인을 받아야 보이며, 공개 안내상 최초 다운로드 후 재다운로드가 1분 동안만 가능하다. 현재 파일명·용량·열 이름·단위·기간·체크섬은 확인할 수 없다.
- 대회 게시판은 참가 등록이 필요하고 리더보드와 제출 화면은 대회 일정에 따라 공개될 예정이다. 일반 공지에서 공개된 2026 공지 3건은 확인했으나 대회 게시판의 공지·FAQ·첨부파일은 열람할 수 없다.

POSTECH 공고는 시상 장소를 “추후 안내 예정”이라고 적고, DataEn 최신 페이지는 부산 BPEX로 구체화한다. 최신 주최 페이지인 DataEn 일정을 우선한다. 부산 외 지역 참가자에게는 교통비를 별도 제공한다고 안내한다.

### 참가 신청 절차

메인 페이지의 “참가 신청 과정 안내” 모달 기준 절차는 다음과 같다.

1. 모든 참가자가 DataEn 회원가입
2. 개인 또는 팀 신청. 팀 신청은 대표자만 진행
3. 운영본부의 참가 자격 검증과 승인
4. 승인 결과를 카카오 알림톡으로 안내

팀명은 최대 10자다. 참가자별 이름, 휴대전화, 대학교, 학적, 기준일로부터 3개월 이내 발급한 재학증명서가 필요하며 팀원을 추가한다. 대학생 팀은 전원이 대학생이어야 하며 팀 구성에 따라 부문이 자동 분류된다. 휴학생은 재학증명서 대신 3개월 이내 발급한 휴학증명서를 낼 수 있다. 이 모달은 별도 “연구자 등록”을 참가 필수 절차로 명시하지 않으므로 DataEn 일반 플랫폼 가이드와 혼동하지 않는다.

## 3. 과제와 배분 조건

전력 시장 직접 참여의 최소 용량을 20 MW로 설명하며, 소규모 태양광 발전소를 VPP로 묶어 판매대금과 예측 오차 페널티를 집합자원 단위로 정산한다. 참가자는 주어진 발전소를 두 집합자원에 나누고 하루 전 발전량을 예측한다. 한 집합의 개선이 다른 집합 구성에 영향을 주므로 두 집합의 전체 정산 결과가 목표다.

공개 데이터 안내에서 확인되는 조건은 다음과 같다.

- `sites.csv`의 253개 발전소를 모두 `composition.csv`에 포함한다.
- 위치 좌표는 원위치에서 최대 2 km 반경 안에서 무작위 이동했다.
- 원좌표 복원과 재식별은 금지된다.
- 공식 설명회 [9:44~11:09](https://www.youtube.com/watch?v=49HZ2kggWNo&t=584s)는 **각 집합의 설비용량 합계가 각각 20,000 kW 이상**이어야 한다고 설명한다. 자동 자막상 전체 제공 용량은 약 42.65 MW, 한 집합에 20 MW를 배정할 때 다른 집합은 약 22.65 MW라는 취지지만 숫자 표기가 깨져 있어 원본 `sites.csv` 용량 합계로 확정해야 한다.
- 같은 구간에서 집합 구성을 평가기간 전체에 대해 한 번 정한다고 설명했다. 다만 대회 중 여러 `composition.csv`를 시험 제출할 수 있는지와 최종 구성 선택 절차는 제출 화면 공개 전이라 확인되지 않았다.

## 4. 제공 데이터 안내

| 데이터 | 공개 안내에서 확인한 내용 | 평가 구간 제공 여부 |
|---|---|---|
| 발전소 메타데이터 | 익명화 위도·경도, 설비용량, 배정된 기상관측지점 | 제공 |
| SMP | 시각별 SMP와 시간대 가중치 `k` | 정확한 범위 미확인 |
| 발전량 실적 | 발전소별 시간별 실제 발전량 | 학습 구간만 제공 |
| 기상예보 | 제공사 A·B의 하루 전 예보 | 학습·평가 모두 제공 |
| 기상실측 | 제공사 A·B의 실측값 | 학습 구간만 제공 |

시간 규칙과 데이터 품질 안내:

- 모든 시각은 KST다.
- 시간별 값은 우측닫힘이다. 예를 들어 `ts=01:00`은 `00:00~01:00`, 즉 `(00:00, 01:00]` 구간이다.
- 예측 시점은 대상일 전일 17:00 KST다. 전일 10시와 17시 예보를 모두 사용할 수 있다.
- 평가 예보에는 결손 264행(0.0247%)이 있으며 이 시각들도 채점한다. 행을 제거하지 말고 대체해야 한다.
- 평가 구간의 기상실측과 발전 실적은 입력으로 제공되지 않는다. 대상일 전일 17시 이후 생성된 정보는 사용할 수 없다.
- 설명회 [19:00~19:46](https://www.youtube.com/watch?v=49HZ2kggWNo&t=1140s)에 따르면 학습 데이터는 2021-01~2025-05이고, [10:57~11:09](https://www.youtube.com/watch?v=49HZ2kggWNo&t=657s)에 따르면 평가기간은 2025-06-01부터 1년(8,760시간)이다. 이 기간은 다운로드 원본 README로 다시 확인해야 한다.
- 설명회 [21:01~22:19](https://www.youtube.com/watch?v=49HZ2kggWNo&t=1261s)는 제공사 A·B의 단위가 서로 다를 수 있으므로 원본 README의 열별 단위를 확인하라고 강조하며, `current_group`은 임의 배정 기준선이지 최적 구성이 아니라고 설명한다.
- 제공된 Python 베이스라인 파일은 제출 흐름을 보여주는 시작 코드라고 설명했다([19:49~20:20](https://www.youtube.com/watch?v=49HZ2kggWNo&t=1189s)). 음성은 “베이스라인 py”로 들리므로 실제 파일명이 `baseline.py`인지는 다운로드 후 확인한다.

다운로드 관련 공개 문구는 “참가 신청 승인 시 제공”, “최초 1회 다운로드, 이후 1분간만 재다운로드”다. 승인 전 화면에서는 다운로드 파일명이나 링크가 노출되지 않았다. 따라서 기존 문서에 적힌 `sites.csv`, `composition.csv` 외의 실제 파일명, 압축 형식, 기간, 열 이름, 단위는 아직 직접 확인하지 못했다.

## 5. 제출 형식과 횟수

- 대회 방식은 최적화한 집합자원과 하루 전 예측 발전량을 **CSV 파일**로 제출하는 것이다.
- 사용 가능 언어는 Python, R이다.
- 제출 제한은 하루 3회, 대회 기간 총 20회다.
- 제출 화면은 현재 “경진대회 진행 일정에 따라 순차적으로 공개됩니다” 상태다.
- 설명회 [22:22~24:42](https://www.youtube.com/watch?v=49HZ2kggWNo&t=1342s) 기준 제출 파일은 두 개다. `composition.csv`는 발전소별 그룹을 담고, 다른 예측 CSV는 집합자원별·타임스탬프별 예측 발전량을 담는다. 자동 자막에서 두 번째 파일명이 탈락했으므로 `forecast.csv`라고 확정하지 않고 템플릿으로 확인한다.
- 예측값은 0 이상의 실수여야 하고, null·무한대·음수가 없어야 하며 타임스탬프에 시간대 표기가 필요하다.
- 정확한 열 이름, 행 순서와 timestamp 문자열 형식은 원본 템플릿을 직접 확인해야 한다.
- 형식 검증 도구는 설명회 당시 배포 여부를 검토 중이었고, 결정 시 홈페이지 공지로 올리겠다고 했다([24:07~24:19](https://www.youtube.com/watch?v=49HZ2kggWNo&t=1447s)).

상위 7개 팀은 다음 자료를 2026-11-23(월)까지 `competition@dershare.xyz`로 제출해야 한다.

- 문제 해결 코드: `.py`, `.ipynb`, `.R`, `.rmd`
- 발표자료: `.pdf`, `.pptx`
- 코드는 데이터 전처리부터 학습과 추론까지 전체 과정을 포함

## 6. 평가와 리더보드

공식 웹 본문의 공개 범위:

- 정산금 `S = 매전수익 - 예측 오차 페널티 W`
- 목표: S 최대화, 설명상 실질적으로 W 최소화
- 순위: S 내림차순
- 상위 7개 팀은 온라인 발표 평가 대상

리더보드에 S(원), W(원), 절대오차 합계(kWh), 정규화 점수(기준선 0점, 완전예측 100점)를 표시한다는 내용은 공식 웹 DOM에서 직접 확인하지 못했고, 공식 내용을 전재한 보조 출처 두 곳에서 확인했다. 리더보드 공개 뒤 실제 열을 재확인해야 한다.

공식 온라인 설명회가 보완한 계산 구조([11:11~14:14](https://www.youtube.com/watch?v=49HZ2kggWNo&t=671s)):

- 집합 `g`, 정산시각 `t`의 실제 집합 발전량을 `A[g,t]`, 제출 예측을 `F[g,t]`라 하면 설명상 매전수익은 `Σ SMP[t] × A[g,t]`다. 예측값은 매전수익 항에 들어가지 않는다.
- 오차 페널티는 `W = Σ_g Σ_t 0.1 × SMP[t] × k[t] × |A[g,t] - F[g,t]|`로 설명됐다.
- `k=3`은 10시부터 15시까지, 나머지 시간은 `k=1`이라고 발표했다. 모든 시각이 우측닫힘 timestamp이므로 정확한 포함 경계는 원본 `smp.csv` 또는 README와 대조해야 한다.
- 설명회 예시 `SMP=120원`, `k=3`, 절대오차 `500 kWh`에서 `W=18,000원`은 `0.1×120×3×500`과 일치한다.
- 한 집합 안 발전소들의 과대·과소 오차는 합산 전에 상쇄되지만, 그룹 1과 그룹 2의 오차는 각 집합에 절댓값을 취해 서로 상쇄되지 않는다.
- 야간을 포함해 제출 대상 모든 시간에 예측값이 있으며, 발전하지 않는 시간에 양수 예측을 내면 페널티가 생긴다고 설명했다.

위 수식은 공식 설명회 음성의 자동 생성 자막과 발표 예시를 교차해 재구성했다. 슬라이드 원본 수식을 직접 확보하지 못했으므로 제공 데이터 README/베이스라인의 scorer가 공개되면 기호와 경계를 최종 대조해야 한다.

아직 확인되지 않은 항목:

- 매전수익의 정확한 합산식
- 비정상 제출을 서버가 거절하는 정확한 검증 규칙과 오류 메시지. 설명회는 음수·null·무한대가 없어야 한다고 했지만 자동 보정 여부는 설명하지 않았다.
- 온라인 발표 평가의 항목, 배점, 최종 순위 반영 방식
- 공개/비공개 리더보드 분할 여부와 최종 채점 기간

설명회 [32:54~34:19](https://www.youtube.com/watch?v=49HZ2kggWNo&t=1974s)에 따르면 제출 직후 리더보드가 갱신되고 팀별 최고 제출 점수가 유지된다. 제출 마감은 2026-11-13 23:59:59 KST라고 별도로 설명했다([5:05~5:13](https://www.youtube.com/watch?v=49HZ2kggWNo&t=305s)). 상위 7팀은 코드 검토와 발표 평가를 거쳐 최종 순위가 바뀔 수 있다. 발표 배점표는 공개되지 않았다.

## 7. 규정과 유의사항

- 제공 데이터는 이 경진대회 목적으로만 사용한다.
- 대상일 전일 17시 KST 이후 생성된 미래 정보(평가 구간 기상실측·발전 실적 등)를 사용하지 않는다.
- 이 조사 당시의 외부 자료 금지 해석은 후속 [운영팀 Q&A](https://dataen.ai/challenge/2026/board/cfe4c0fc-7951-4ee9-b293-4730e42029ec)로 수정됐다. 공개·상업적 이용 가능한 외부 소스·모델은 허용된다.
- 설명회 Q&A [35:17~36:06](https://www.youtube.com/watch?v=49HZ2kggWNo&t=2117s)는 코드 작성·분석 정리에 생성형 AI를 사용할 수 있다고 답했지만, 제공 데이터를 외부 API나 생성형 AI 서비스에 업로드하거나 저장·학습시키는 행위는 금지했다.
- 이어지는 Q&A [36:06~36:37](https://www.youtube.com/watch?v=49HZ2kggWNo&t=2166s)는 참가자가 자체 구성한 서버에서 학습할 수 있으나 대회 종료 뒤 30일 안에 데이터를 폐기해야 하고, 타사 외부 서비스에 제공 데이터를 올리거나 저장하는 것은 금지한다고 설명했다. 이 규정은 자동 자막이 아니라 해당 음성 구간을 다시 확인할 우선 항목으로 남긴다.
- 여러 팀에 중복 참가할 수 없고 계정 중복 생성은 실격과 수상 취소 사유다.
- 팀 간 담합과 계정 중복을 금지한다. 제출 결과 유사도가 기준을 넘으면 소명을 요구하며 실패 시 실격 처리한다.
- 최우수상 대학생 부문은 팀원 전원이 대학생이어야 한다.
- 제출물 지식재산권은 참가자에게 있고 주최·주관·후원사는 수상작 사용권을 가진다.

## 8. 시상 내역과 공식 자료 간 명칭 차이

DataEn 현재 페이지는 대상 1팀 500만 원, 최우수상 2팀(대학생·대학원생 각 1팀) 각 200만 원, 우수상 4팀 각 100만 원, 장려상 10팀 각 40만 원으로 안내한다. 총 17팀, 1,700만 원이다.

POSTECH 2026-09-22 공고/PDF는 금액과 팀 수는 같지만 명칭을 대상 1팀, 우수상 2팀, 장려상 4팀, 참가상 10팀으로 적었다. 제세공과금은 본인 부담이며 시상식 참석 대상을 대상·우수상 수상팀으로 적었다. 최신 DataEn 명칭을 대회 운영 기준으로 보고, 명칭 차이는 주최 측 확인이 필요하다.

## 11. 접근 한계와 후속 확인 목록

현재 시점에 공개되지 않았거나 참가 승인 뒤에만 접근 가능한 정보가 있어 “필요한 정보 전부”를 실제 파일 수준까지 확정할 수는 없다.

1. 참가 승인 후 제공 데이터 원본 파일명·크기·해시·기간·열·단위·결측 분포 확인
2. 최초 다운로드 즉시 안전한 사본과 해시 보관(재다운로드 1분 제한)
3. 대회 게시판의 2026 공지·FAQ·정정 공지·첨부파일 확인
4. 제출 화면 공개 후 CSV 템플릿과 validation 규칙 확인
5. 리더보드 공개 후 public/private 분할, 채점 기간과 갱신 주기 확인
6. 제공 README와 자체 계산으로 W·S·SMP·`k` 식과 시간 경계, 단위를 확인한다. 운영팀은 원본 `scoring.py`를 배포하지 않는다.
7. 발표 평가 배점과 최종 수상 순위 반영 방식 확인
8. 여러 `composition.csv`를 시험 제출할 수 있는지와 최종 구성 선택 절차 확인(평가기간의 최종 구성은 고정)
